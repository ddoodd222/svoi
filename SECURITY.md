# Как устроена защита «Своих»

Документ для тех, кто хочет проверить защиту сам. Код криптографии — `web/js/crypto.js`, канал — `web/js/signal.js`, комната — `web/js/room.js`.

## Модель угроз

**От чего защищает:**

- Посредники, через которые устройства находят друг друга (публичные MQTT-брокеры EMQX и HiveMQ). Они видят только зашифрованные посылки.
- Хостинг страницы (GitHub Pages). Секрет комнаты стоит после `#` и не попадает в HTTP-запрос.
- Сеть между участниками: провайдер, Wi-Fi в кафе, TURN-ретранслятор.
- Человек, у которого есть ссылка, но которого хозяин не впустил.
- Участник, которого хозяин удалил из встречи.
- Подмена собеседника посередине (MITM) при обмене ключами.

**От чего не защищает:**

- Взломанное устройство участника.
- Участник, который записывает звонок.
- Подмена кода веб-версии на GitHub Pages, если взломан аккаунт GitHub. Приложение для Android от этого защищено: код страницы лежит внутри APK.
- Метаданные. Брокер видит IP-адреса устройств, время и объём служебных сообщений. Участники звонка видят IP-адреса друг друга. Скрыть IP можно режимом «всегда через ретранслятор».
- Обладатель ссылки, которого не впустили, видит в канале шум, приветствия хозяина (его открытые ключи и флаг «вход закрыт») и сигнал «встреча завершена». Кто стучится, кто в комнате и кто кому пишет — ему не видно.

## Ключи

| Что | Как получается | Где живёт |
|---|---|---|
| Секрет комнаты `S` | 32 случайных байта | только в ссылке после `#` и у хозяина в localStorage |
| Адрес канала | `HKDF-SHA256(S, "topic")`, 16 байт | известен брокеру; из него `S` не восстановить |
| Ключ канала | `HKDF-SHA256(S, "signal-aes")` → AES-256-GCM | в памяти |
| Ключ подписи участника | ECDSA P-256, закрытый ключ неизвлекаемый | IndexedDB этого устройства |
| Ключ конвертов участника | ECDH P-256, закрытый ключ неизвлекаемый | IndexedDB этого устройства |
| Id участника | `SHA-256("id" ‖ подпись ‖ конверт)`, 132 бита | вычисляется из открытых ключей |
| Личный конверт | новый одноразовый ECDH-ключ `e` на каждое письмо; `HKDF(ECDH(e, получатель) ‖ S ‖ e, "box|id получателя")` → AES-256-GCM | в памяти |
| Добавка к коду `r` | 9 случайных байт, хозяин придумывает после стука и шлёт гостю в личном конверте | у хозяина и гостя |
| Код проверки | `SHA-256("code|" ‖ S ‖ "|" ‖ id ‖ "|" ‖ r)` → 9 цифр | показывается на экране |
| Сеанс хозяина `hs` | 12 случайных байт на каждое открытие комнаты | в памяти |

Id хозяина зашит в ссылку параметром `h`. Подделать его без закрытого ключа хозяина нельзя.

## Служебное сообщение

1. Конверт `{v, type, from, pk, to, ts, n, body}` подписан ECDSA ключом отправителя. Подпись покрывает и получателя `to`.
2. Если сообщение адресовано одному участнику, подписанный конверт целиком запечатан в личный конверт получателю.
   Снаружи нет ни отправителя, ни получателя, ни типа. Получатель пробует открыть каждый личный конверт; чужой не открывается.
3. Всё вместе зашифровано ключом канала (AES-256-GCM, AAD — адрес канала).
4. Посылка уходит сразу через два брокера. Получатель отбрасывает дубли по вектору инициализации,
   но только после успешной расшифровки: мусор с тем же вектором не заглушит настоящую копию.

Получатель отбрасывает сообщение, если:

- не сходится AES-GCM ключа канала (нет ссылки);
- личный конверт не открывается (письмо не ему);
- получатель внутри подписи не совпадает с тем, кому запечатан конверт (подписанное письмо переложили другому);
- id отправителя не равен хэшу его открытых ключей;
- не сходится подпись;
- метка времени отличается больше чем на 10 минут, или номер `n` уже встречался (повтор).

## Допуск в комнату

1. Хозяин раз в 4 секунды рассылает `hello`: свои открытые ключи, флаг «вход закрыт» и номер сеанса `hs`.
   Гость проверяет, что хэш ключей равен `h` из ссылки, и запоминает `hs` из самого свежего приветствия.
2. Гость шлёт `knock` с именем в личном конверте хозяину.
3. Хозяин придумывает случайную добавку `r` и шлёт её гостю в личном конверте. Оба видят код из `S`, id гостя и `r`.
   Ключ гостя к этому моменту уже известен, `r` — ещё нет. Поэтому подобрать ключ под чужой код нельзя.
   Чужого кода к тому же не видно: и стук, и добавка запечатаны.
4. Хозяин сверяет код голосом и впускает. Список участников с версией уходит каждому участнику в личном конверте, подписанный хозяином.
5. Команды хозяина (`challenge`, `roster`, `deny`, `end`) принимаются только с `hs` текущего сеанса.
   Повтор «встреча завершена» из прошлой встречи в новой не сработает.
6. Список участников принимается только с версией новее текущей. Версия перепроверяется после проверки ключей.

Удалённый участник исчезает из списка. Остальные сразу рвут с ним соединения и не принимают его предложения.
Отказы и удаления хозяин хранит вместе с комнатой. После перезагрузки страницы удалённый не войдёт.
При закрытом входе хозяин отвечает отказом, не показывая запрос и не выдавая код.

Участник, который на минуту пропал из сети, возвращается без нового запроса: хозяин помнит его ключ 3 минуты.
Если спал телефон хозяина, участников не выкидывает: хозяин замечает пропуск в своих часах и ждёт их отклика.

Хозяин завершил встречу — список участников и закрытый вход сбрасываются.
В следующую встречу все снова стучатся и сверяют новый код.

## Звонок

- Между каждой парой участников — своё соединение WebRTC. Медиа шифруется DTLS-SRTP, чат — DTLS (SCTP).
- Предложение и ответ SDP (там отпечаток DTLS-сертификата и сетевые адреса) идут в личном конверте, подписанном отправителем.
  Браузер проверяет, что DTLS-сертификат собеседника совпадает с отпечатком. Подменить его посередине нельзя: для этого нужна подпись.
- Предложения принимаются только от участников из подписанного хозяином списка.
- TURN-ретранслятор, если включён, видит только зашифрованный DTLS-SRTP.

## Страница

- Content Security Policy: скрипты, стили и шрифты только со своего адреса; сеть — только два брокера.
- Trusted Types: страница не использует `innerHTML`, чужой текст попадает только через `textContent`.
- Нет сторонних скриптов, шрифтов и счётчиков. QR-генератор лежит рядом (MIT, без изменений).
- Страница отказывается работать внутри чужого `iframe`.
- Секрет убирается из адресной строки сразу после открытия ссылки.
- `Referrer-Policy: no-referrer`.

## Приложение для Android

- Страница лежит внутри APK и открывается по служебному адресу `https://appassets.androidplatform.net`. Код из интернета не загружается.
- Мост к телефону (`addWebMessageListener`) открыт только для этого адреса и только для главного фрейма.
- Переход на любой другой адрес открывается во внешнем браузере, а не внутри приложения.
- Доступ к камере и микрофону выдаётся только этой странице.
- Резервное копирование выключено: ключи не уезжают в облако и на другой телефон.
- Показ экрана — системный MediaProjection с запросом согласия. Кадры идут только в звонок.

## Проверено

`tests/channel.test.mjs` — на настоящих брокерах:
третий участник не открывает личный конверт и не видит, кто кому писал; у каждого конверта свой ключ; код зависит от добавки хозяина;
без ключа комнаты посылки не читаются; подделка текста ловится подписью; дубли отбрасываются. 16 пунктов.

`tests/e2e.test.mjs` — звонок втроём в Chrome:
код у хозяина совпадает с кодом гостя; секрет убран из адресной строки; удалённый участник выходит из звонка;
при закрытом входе запросы до хозяина не доходят, а гость не получает кода; HTML в чате остаётся текстом;
после завершения встречи прошлый гость снова стучится, а не входит сам. 35 пунктов.
